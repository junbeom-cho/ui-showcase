# UI 컴포넌트 쇼케이스 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** UI 컴포넌트 이름(Skeleton, Sidebar, Grid, Card, Badge, Avatar 등)과 실제 모양을 한 페이지 갤러리에 나란히 보여주고, 이름·별칭·설명으로 검색할 수 있는 정적 웹앱을 만든다.

**Architecture:** 컴포넌트마다 `ShowcaseEntry`(id, 이름, 별칭, 한 줄 설명, 미리보기 컴포넌트)를 파일 하나에 정의하고, `registry.ts`가 이를 이름순으로 모은다. `Gallery`는 검색어로 `filterEntries`를 거친 항목을 `ShowcaseCard` 그리드로 렌더링한다. 미리보기는 shadcn/ui 컴포넌트로 만들고, shadcn/ui에 없는 개념(Grid)만 Tailwind로 직접 만든다.

**Tech Stack:** React, Vite, TypeScript, Tailwind CSS v4 (`@tailwindcss/vite`), shadcn/ui, Vitest + jsdom + React Testing Library

**Spec:** 별도 스펙 문서 없음. [DECISION.md](../../../DECISION.md)의 D-003 ~ D-006이 요구사항이다. 그 밖의 내용(컴포넌트 목록, 문구, 검색 규칙)은 이 계획에서 정한 것이며 아래에 "계획 작성자 결정"으로 표시했다.

## Global Constraints

- 스택: React + Vite + TypeScript + Tailwind CSS (D-004). 다른 프레임워크·CSS 라이브러리는 추가하지 않는다.
- 미리보기는 shadcn/ui 컴포넌트로 만든다. shadcn/ui에 없는 개념만 Tailwind로 직접 만든다 (D-005).
- 화면은 한 페이지 갤러리 하나다. 라우터를 넣지 않는다 (D-006).
- 코드·식별자는 영어로, 화면에 보이는 설명 문구는 한국어로 작성한다 (CLAUDE.md, 화면 문구 언어는 계획 작성자 결정).
- 커밋 메시지는 CLAUDE.md의 커밋 컨벤션(D-008)을 따른다: `<type>(<scope>): <한국어 명사형 설명>`, Co-Authored-By 트레일러 없음.
- **커밋은 사용자가 요청할 때만 한다 (CLAUDE.md).** 각 태스크의 커밋 단계는 사용자가 태스크별 커밋을 허용한 경우에만 실행한다. 허용하지 않았다면 그 단계를 건너뛴다.
- 컴포넌트 이름(`name`)은 shadcn/ui 문서의 영문 표기를 그대로 쓴다.
- 모든 미리보기는 카드 안에서 끝나야 한다. 페이지 전체를 덮는 `fixed` 배치나 375px 폭에서 가로 스크롤을 만들면 안 된다 (열린 Dialog·Sheet 오버레이는 예외).
- Node.js는 mise로 관리하고 `mise.toml`에 `node = "26"`으로 고정한다 (D-007).

### Task 2: 데이터 타입과 검색 함수

**Files:**
- Create: `src/showcase/types.ts`, `src/showcase/filter-entries.ts`
- Test: `src/showcase/filter-entries.test.ts`

**Interfaces:**
- Produces:
  ```ts
  // src/showcase/types.ts
  import type { ComponentType } from 'react'
  export type ShowcaseEntry = {
    id: string            // kebab-case, also used as the card's DOM id
    name: string          // English name as shadcn/ui writes it
    aliases: string[]     // other names for the same UI (other libraries, Korean)
    description: string   // one Korean sentence
    Preview: ComponentType
  }
  // src/showcase/filter-entries.ts
  export function filterEntries(entries: ShowcaseEntry[], query: string): ShowcaseEntry[]
  ```

검색 규칙(계획 작성자 결정): 검색어의 앞뒤 공백을 지우고 소문자로 바꾼다. 비어 있으면 원래 배열 순서 그대로 전부 돌려준다. 아니면 `name`, `aliases`의 각 항목, `description` 중 하나라도 (소문자로 바꿔) 검색어를 부분 문자열로 포함하는 항목만, 원래 순서대로 돌려준다.

- [ ] **Step 1: 실패하는 테스트를 작성한다**

테스트용 항목 3개를 둔다. `Preview`는 `() => null`이다.
- badge: name `Badge`, aliases `['Tag', 'Chip']`, description `'상태를 표시하는 작은 라벨.'`
- dialog: name `Dialog`, aliases `['Modal']`, description `'화면 위에 뜨는 창.'`
- skeleton: name `Skeleton`, aliases `[]`, description `'로딩 중 자리표시자.'`

```ts
it('returns all entries in order for an empty or blank query', () => {
  expect(filterEntries(items, '')).toEqual(items)
  expect(filterEntries(items, '   ')).toEqual(items)
})
it('matches name case-insensitively and ignores surrounding spaces', () => {
  expect(filterEntries(items, '  BADGE ').map(e => e.id)).toEqual(['badge'])
})
it('matches aliases', () => {
  expect(filterEntries(items, 'modal').map(e => e.id)).toEqual(['dialog'])
})
it('matches Korean description text', () => {
  expect(filterEntries(items, '로딩').map(e => e.id)).toEqual(['skeleton'])
})
it('returns an empty array when nothing matches', () => {
  expect(filterEntries(items, 'carousel')).toEqual([])
})
```

import { entries } from './registry'

const ids = () => entries.map(e => e.id)

it('has unique kebab-case ids and non-empty text', () => {
  expect(new Set(ids()).size).toBe(entries.length)
  for (const e of entries) {
    expect(e.id).toMatch(/^[a-z]+(-[a-z]+)*$/)
    expect(e.name.trim()).not.toBe('')
