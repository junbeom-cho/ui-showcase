# 디자인 스타일 페이지 설계

- 날짜: 2026-11-12
- 관련 결정: D-012(디자인 스타일 페이지), D-013(3D 아이콘 이미지), D-014(배경·질감 이미지), D-010(사이드바 + 페이지), D-011(해부도 디자인), D-004·D-005(스택)
- 표시 규칙: **[사용자]**는 사용자가 직접 정한 것, **[작성자 판단]**은 이 문서를 쓴 쪽이 정한 것, **[빌더 재량]**은 구현하는 사람이 정하면 되는 것

## 1. 의도

이 프로젝트는 UI 이름과 생김새를 연결해 외우기 위한 학습용 쇼케이스다(D-003). 지금은 컴포넌트(Button, Card 등)만 다룬다. 사용자는 "뉴모피즘", "글래스모피즘" 같은 **디자인 스타일 이름**도 같은 방식으로 익히고 싶어 한다.

핵심 경험은 이렇다. 사이드바에서 스타일을 하나씩 옮겨 다니면 **같은 화면이 모양만 바뀐다.** 내용과 배치가 그대로이므로 차이는 스타일에서만 나온다. 그 차이를 보고 "아, 이게 뉴모피즘이구나"를 알아보게 하는 것이 목표다.

사용자가 처음 바란 것은 기존 컴포넌트 페이지 전체에 테마를 입히는 방식이었다. 범위가 너무 커서 대신 이 구조를 택했다 **[사용자]**.

## 2. 목표 · 하지 않을 것 · 실패로 볼 것

**목표**
- 9개 스타일 각각의 페이지에서 같은 데모 화면이 그 스타일로 보인다.
- 스타일마다 알아보는 특징 3~4가지를, 데모 위 번호 표시와 함께 설명한다.
- 스타일 첫 화면에서 9개를 썸네일로 한눈에 비교한다.
- 사이드바와 검색에서 컴포넌트와 똑같이 스타일을 찾아간다.

**이번에 하지 않을 것**
- 기존 컴포넌트 페이지(Card, Button 등)에 스타일을 입히는 테마 전환
- 다크 모드
- 추가로 제안한 스타일(미니멀리즘, 플루언트, Y2K, 벤토 그리드, 오로라 그라디언트, 멤피스). 나중에 따로 결정한다 **[사용자]**
- 빠진 컴포넌트(토스트, 스낵바, 페이지 상단 배너, 바텀시트 항목, 인라인 오류, 코치마크). 별도 작업이다 **[사용자]**
- 실제 브랜드(Apple, Google, Microsoft)의 로고, 이름이 들어간 화면 흉내. 스타일의 특징만 보여준다

**실패로 볼 것** (기술적으로 동작해도)
- 서로 다른 두 스타일이 썸네일에서 구분되지 않는다. 특히 뉴모피즘과 클레이모피즘, 글래스모피즘과 리퀴드 글래스를 구분하기 어려우면 실패다.
- 스타일을 바꿨을 때 데모의 글, 배치, 요소 수가 달라진다. 비교 기준이 무너진다.
- 스타일 CSS가 데모 밖(사이드바, 기존 컴포넌트 페이지)으로 새어 나간다.
- 데모 글을 읽을 수 없다. 뉴모피즘의 "낮은 대비"는 특징으로 보여주되, 본문 글은 읽을 수 있어야 한다.

## 3. 화면과 주소

| 주소 | 화면 |
|---|---|
| `#/` | 지금의 컴포넌트 개요 (변경 없음) |
| `#/<component-id>` | 지금의 컴포넌트 페이지 (변경 없음) |
| `#/styles` | 디자인 스타일 첫 화면: 9개 썸네일 격자 **[사용자: 격자]** |
| `#/style/<style-id>` | 스타일 페이지 **[사용자]** |
| 없는 스타일 id | 기존 컴포넌트와 같은 형식의 "찾을 수 없습니다" 안내와 `#/styles`로 돌아가는 링크 **[작성자 판단]** |

라우터 라이브러리 없이 지금의 해시 라우팅(`src/showcase/route.ts`)을 넓힌다(D-010).

### 3.1 사이드바 [작성자 판단]

지금 사이드바(검색 + "개요" + 컴포넌트 분류 6개) 아래에 묶음을 하나 더 둔다.

```
[검색]
개요
레이아웃 / 내비게이션 / … / 오버레이   (지금 그대로)
─────────
디자인 스타일            ← 묶음 제목
  전체 보기              → #/styles
  스큐어모피즘           → #/style/skeuomorphism
  플랫 디자인
  …
  리퀴드 글래스
```

- 사이드바의 스타일 항목은 한국어 이름으로 표시한다. 사용자가 한국어로 불렀다.
- 검색은 컴포넌트와 스타일을 함께 거른다. 스타일은 한국어 이름, 영어 이름, 다른 이름, 설명으로 찾는다. 예: "Soft UI"로 검색하면 뉴모피즘이 나온다.
- 현재 위치 표시(`aria-current`)와 모바일 Sheet 동작은 지금과 같다.

### 3.2 스타일 페이지 [사용자 + 작성자 판단]

위에서 아래 순서:

1. 빵부스러기 경로: `개요 › 디자인 스타일 › 뉴모피즘`. "디자인 스타일"은 `#/styles` 링크다.
2. 제목(h1): 한국어 이름. 그 아래 영어 이름과 다른 이름 배지, 한 줄 설명 **[사용자: 컴포넌트 페이지처럼]**
3. 짧은 맥락 한 줄: 언제 유행했고 대표 사례가 무엇인지 **[작성자 판단]**. 예: "2013년 iOS 7, Windows 8의 Metro와 함께 퍼졌다." 브랜드 로고는 쓰지 않는다.
4. **데모 + 특징**: 컴포넌트 페이지의 해부도(`Anatomy`)를 재사용한다 **[작성자 판단]**.
   - 왼쪽(넓은 화면 기준)에 그 스타일의 데모, 오른쪽에 번호가 붙은 특징 목록을 둔다.
   - **기본 상태에서는 번호 표시를 끈다.** 데모는 깨끗하게 먼저 보여야 하기 때문이다. 특징 하나에 마우스를 올리거나 포커스하면 그 특징의 윤곽, 지시선, 번호만 나타난다. "특징 번호 모두 표시" 스위치를 켜면 전부 보인다. 컴포넌트 페이지는 지금처럼 기본으로 켜 둔다.
   - 특징 목록의 이름은 코드 이름이 아니라 한국어 문구다(예: "밝은 그림자와 어두운 그림자 한 쌍"). 컴포넌트 페이지처럼 고정폭 글꼴로 쓰지 않는다.
5. 이전·다음 스타일 링크. 순서는 사이드바 순서다.

데모는 직접 만질 수 있어야 한다. 스위치를 켜고 끄고, 버튼을 누르고, 입력칸에 포커스할 수 있어야 한다. 눌림(뉴모피즘·스큐어모피즘의 오목해짐), 포커스, 켜짐 상태가 스타일의 중요한 부분이기 때문이다 **[작성자 판단]**.

### 3.3 스타일 첫 화면 `#/styles` [사용자: 격자]

- 제목, 한 줄 소개, 9개 카드 격자. 카드 위쪽에 그 스타일로 그린 데모를 축소해 보여주고, 아래에 한국어 이름과 영어 이름을 둔다. 카드를 누르면 스타일 페이지로 간다.
- 썸네일은 실제 데모를 축소 렌더링한다. 정적 이미지를 쓰지 않는다. 썸네일 안은 조작할 수 없게 한다(`inert`) **[작성자 판단]**.
- 격자는 화면 폭에 따라 1~3열이다. 375px에서 가로 스크롤이 없어야 한다.

## 4. 데모 화면 (모든 스타일 공통) [사용자: "일반 앱 화면(프로필·설정)"]

모든 스타일에서 내용과 배치가 같다. 들어가는 요소:

| 요소 | 내용 | 쓰는 컴포넌트 |
|---|---|---|
| 프로필 | 아바타, 이름 "김하늘", 배지 "프로" | Avatar, Badge |
| 검색 | 입력칸, placeholder "설정 검색", 앞에 검색 아이콘 | Input, 아이콘 |
| 설정 줄 1 | 아이콘(종) + "알림 받기" + 스위치(켜짐) | Switch, 아이콘 |
| 설정 줄 2 | 아이콘(구름) + "자동 백업" + 스위치(꺼짐) | Switch, 아이콘 |
| 저장 공간 | 아이콘(폴더 또는 상자) + "저장 공간" + 70% 막대 + "70%" | Progress, 아이콘 |
| 버튼 | "저장"(주 버튼), "취소"(보조 버튼) | Button |
| 바탕 | 데모 카드 뒤 배경. 스타일마다 다름(아래 5절) | — |

- 데모 전체를 하나의 카드(Card)로 감싼다. 크기는 휴대폰 화면 정도다(폭 약 320px).
- **같은 컴포넌트에 옷만 바꿔 입힌다** **[작성자 판단]**. 데모는 지금 쓰는 shadcn 컴포넌트로 한 번만 만든다. 스타일은 데모를 감싼 요소의 속성(예: `data-design-style="neumorphism"`)으로 범위를 정한 CSS로만 입힌다. shadcn 컴포넌트에 이미 붙어 있는 `data-slot`(button, card, switch, input, progress, badge, avatar 등)을 선택자로 쓴다.
  - 결과적으로 쇼케이스의 Button과 스타일 페이지의 Button이 같은 부품이 된다. 이 연결 자체가 학습 포인트다.
  - 스타일 CSS가 데모 밖으로 새면 안 된다(2절 실패 조건).
- 아이콘은 기본적으로 지금 쓰는 lucide 아이콘이다. 3D 아이콘 스타일에서만 같은 자리를 3D 이미지로 바꾼다. 아이콘 자리 수와 위치는 같게 유지한다.
- 특징 번호가 가리킬 수 있도록, 데모 안의 주요 요소에 `data-slot`이 있어야 한다. 아이콘 자리, 바탕처럼 shadcn에 없는 것은 데모에서 직접 붙인다.

## 5. 스타일별 내용 [작성자 판단, 사용자 확인 대상]

스타일마다 id, 한국어 이름, 영어 이름·다른 이름, 한 줄 설명, 맥락 한 줄, 특징 3~4개, 데모 바탕을 정한다. 아래는 내용의 기준이다. 정확한 CSS 값은 **[빌더 재량]**이다. 단, 2절의 "구분되어야 함" 조건을 지켜야 한다.

| id | 이름 | 다른 이름 | 한 줄 설명 | 알아보는 특징 (3~4) | 바탕 |
|---|---|---|---|---|---|
| `skeuomorphism` | 스큐어모피즘 | Skeuomorphism, Realism | 실제 물건의 재질·빛·질감을 흉내 낸 스타일 | 가죽·금속·종이 같은 재질 질감 / 위에서 비추는 빛의 광택과 그라디언트 / 볼록한 버튼과 오목하게 파인 입력칸·스위치 홈 / 바느질선·나사 같은 사실적 디테일 | 질감 있는 어두운 바탕(나무나 리넨 느낌) |
| `flat` | 플랫 디자인 | Flat design, Metro | 그림자·그라디언트·질감 없이 단색 면과 선명한 색만 쓰는 스타일 | 단색 면 / 그림자 없음 / 선명한 원색 / 단순한 선 아이콘과 큰 글자 | 단색 |
| `material` | 머티리얼 | Material Design, Material You | 종이 같은 면이 높이(층)를 가지고, 그림자로 위아래를 표현하는 구글의 디자인 언어 | 높이에 따라 달라지는 그림자(elevation) / 누를 때 퍼지는 물결(ripple) / 알약 모양 버튼과 큰 둥근 모서리(M3) / 한 가지 색에서 뽑은 톤 팔레트 | 연한 톤 색 |
| `neumorphism` | 뉴모피즘 | Neumorphism, Soft UI | 배경과 같은 색의 요소가 바탕에서 튀어나오거나 파인 듯 보이는 스타일 | 요소 색 = 배경 색 / 왼쪽 위 밝은 그림자 + 오른쪽 아래 어두운 그림자 한 쌍 / 눌리면 안쪽 그림자로 파임 / 낮은 대비(접근성 약점) | 연한 회색 단색 |
| `glassmorphism` | 글래스모피즘 | Glassmorphism, Frosted glass | 뒤가 흐리게 비치는 반투명 유리판을 겹친 스타일 | 뒤 배경을 흐리게 하는 블러 / 반투명한 흰 바탕 / 얇고 밝은 테두리 / 뒤에 화려한 배경이 있어야 효과가 남 | 선명한 색 번짐(그라디언트 덩어리) |
| `claymorphism` | 클레이모피즘 | Claymorphism, Clay UI | 점토로 빚은 듯 말랑하고 통통한 입체 스타일 | 아주 큰 둥근 모서리 / 바깥 그림자 + 안쪽 위 밝은 그림자 + 안쪽 아래 어두운 그림자 / 파스텔 색 / 떠 있는 듯한 부피감 | 밝은 파스텔 |
| `neo-brutalism` | 네오 브루탈리즘 | Neo-brutalism, Neubrutalism | 굵은 검은 테두리와 흐림 없는 그림자로 투박하게 꾸민 스타일 | 굵은 검은 테두리 / 블러 없이 어긋난 단단한 그림자 / 강한 원색 / 각지거나 투박한 글자와 정렬 | 원색 단색 |
| `3d-icons` | 3D 아이콘 | 3D icons, 3D illustration | 렌더링한 입체 아이콘을 주인공으로 두고 나머지는 깔끔하게 둔 스타일 | 조명과 질감이 있는 입체 아이콘 / 아이콘이 크고 눈에 띔 / 나머지 UI는 단순하고 밝음 / 부드러운 그림자 | 밝은 단색 또는 옅은 그라디언트 |
| `liquid-glass` | 리퀴드 글래스 | Liquid Glass | 가장자리에서 빛이 휘고 반사되는, 물방울 같은 유리 스타일 | 가장자리의 굴절(뒤 배경이 휘어 보임) / 가장자리를 따라 흐르는 반사 하이라이트 / 매우 투명함(글래스모피즘보다 덜 흐림) / 콘텐츠 위에 떠 있는 캡슐 모양 컨트롤 | 사진처럼 색과 형태가 있는 배경 |

맥락 한 줄(예시, 빌더가 다듬어도 됨):
- 스큐어모피즘: iOS 6 이전 아이폰 앱처럼 2000~2012년 무렵 널리 쓰였다.
- 플랫: 2012~2013년 Windows 8의 Metro, iOS 7과 함께 퍼졌다.
- 머티리얼: 2014년 구글이 발표했고, 2021년 Material You(M3)로 바뀌었다.
- 뉴모피즘: 2019~2020년 디자인 공유 사이트를 중심으로 유행했다.
- 글래스모피즘: 2020년 무렵 macOS Big Sur, Windows의 반투명 소재와 함께 퍼졌다.
- 클레이모피즘: 2021년 무렵 일러스트와 앱 시안에서 퍼졌다.
- 네오 브루탈리즘: 2021~2022년 무렵 개인 웹사이트, 스타트업 랜딩 페이지에서 유행했다.
- 3D 아이콘: 2020~2021년 무렵 3D 렌더 아이콘과 이모지 세트가 공개되며 퍼졌다.
- 리퀴드 글래스: 2025년 애플이 운영체제 전반에 도입했다.

연도가 정확하지 않을 수 있다. 빌더는 확신이 없는 연도를 "~무렵"으로 쓰거나 뺀다 **[빌더 재량]**.

### 5.1 구분이 어려운 짝 (실패 조건과 연결)

- **뉴모피즘 vs 클레이모피즘**: 뉴모피즘은 요소 색이 배경 색과 같고 그림자로만 형태가 보인다. 클레이모피즘은 요소가 배경과 다른 파스텔 색이고 통통한 부피감(안쪽 그림자)이 있다.
- **글래스모피즘 vs 리퀴드 글래스**: 글래스모피즘은 뒤를 많이 흐리고 바탕이 하얗게 탁하다. 리퀴드 글래스는 거의 투명하고, 가장자리에서 배경이 휘어 보이며 반사광이 있다.

### 5.2 리퀴드 글래스의 브라우저 차이

- 굴절(배경이 휘어 보이는 효과)은 SVG 필터와 `backdrop-filter`의 조합으로 만든다. 이 조합은 Chrome 계열에서만 제대로 동작한다.
- 그 밖의 브라우저에서는 가장자리 하이라이트와 약한 블러만 있는 유리로 대신 보여준다. 깨진 모양이나 빈 화면이 나오면 안 된다.
- 페이지에 "굴절 효과는 Chrome 계열 브라우저에서 가장 잘 보입니다" 같은 안내를 한 줄 둔다 **[작성자 판단]**.
- 구현 기법 자체는 **[빌더 재량]**.

## 7. 지켜야 할 것 (제약)

- 스택: React + Vite + TypeScript + Tailwind v4 + shadcn/ui(D-004, D-005). 새 런타임 의존성은 꼭 필요할 때만 쓰고, 쓸 경우 이유를 남긴다.
- 사이드바·페이지 틀 같은 앱 바깥 모양은 지금의 도면 스타일(D-011)을 유지한다. 스타일은 데모 안에서만 바뀐다.
- 반응형: 375px에서 가로 스크롤이 없어야 한다. 데모 카드는 좁은 화면에서 폭을 줄인다.
- `prefers-reduced-motion`을 존중한다(ripple, 반짝임 같은 움직임).
- 키보드 포커스가 모든 스타일에서 보여야 한다.
- 기존 컴포넌트 페이지와 개요의 동작은 바뀌지 않아야 하고, 그 동작을 지키는 기존 테스트는 그대로 통과해야 한다. 사이드바처럼 이번 작업으로 **의도해서 바뀌는 부분**의 테스트는 새 동작에 맞게 고친다. 예를 들어 사이드바 검색이 스타일까지 찾게 되면 검색창 이름과 "일치하는 항목이 없다"는 문구를 컴포넌트·스타일 모두에 맞게 바꾸고 테스트도 함께 고친다. 사이드바는 하나의 목록(nav)으로 합친다 **[작성자 판단]**.
- 결정은 DECISION.md에 기록한다. 커밋은 사용자가 요청할 때만 한다(CLAUDE.md).

## 8. 테스트로 확인할 것 [작성자 판단]

- 주소 해석: `#/styles`, `#/style/neumorphism`, `#/style/neumorphism/`, 없는 스타일 id, 기존 `#/badge`가 여전히 컴포넌트로 해석되는지

- 데모 공통성: 9개 스타일 모두 데모 안의 텍스트가 같음(내용이 스타일마다 달라지지 않음)
- 사이드바: "디자인 스타일" 묶음과 9개 링크, "전체 보기" 링크, 현재 스타일 표시, 검색("Soft UI" → 뉴모피즘)
- 스타일 페이지: h1, 다른 이름, 특징 목록, 기본 상태에서 번호 표시 없음, 특징에 마우스를 올리면 해당 번호만 나타남
- 스타일 첫 화면: 9개 카드, 각 카드가 맞는 주소로 연결됨
- 브라우저 확인(자동 테스트 불가): 9개 스타일이 썸네일에서 서로 구분되는지(특히 5.1의 두 짝), 375px 가로 스크롤 없음, 리퀴드 글래스의 Chrome과 대체 표시, 3D 이미지 로딩
